## 기능 별 책임을 분리

### 상품 컨텍스트
판매자가 등록한 상품 정보와 재고 수량을 관리한다

+ 소유 데이터
    - 상품
        + 상품명, 설명, 가격, 판매상태, 판매자 ID 등
    - 재고
        + 가용수량, 예약수량
+ 변경 이유
    - 상품 정보
        + 판매자의 상품 등록, 수정
        + 플랫폼의 검수, 노출 정책
    - 재고
        + 판매자의 입고 등록
        + 주문에 의한 자동 예약, 차감
+ 분리 가능성
    - 재고는 주문마다 변경되어 쓰기 경합이 발생하지만 상품 정보는 읽기 위주
    - 상품 정보는 사람만 변경하는 반면에 재고는 주문 시스템이 자동으로 변경
    - 현재 범위 내에서는 하나의 컨텍스트로 두되 재고 경합이 문제가 되면 분리할 수 있다

|컨텍스트|변경 이유|수명 주기|트랜잭션 범위|
|---|---|---|---|
|주문|구매, 취소 정책|||
|상품|판매자의 상품 등록, 재고 입고, 플랫폼 검수 정책|주문과 무관|불필요 (재고 예약모델)|
|결제|PG사 스펙, 결제수단 추가 (외부)|주문보다 긴 트랜잭션 (응답을 주고받아야 하므로)|불가능 (외부 호출)|
|정산|수수료율, 정산주기|주문보다 길다|불필요|

주문은 확정되면 상태 변화가 끝나지만 정산은 주문이 끝난 시점부터 집계, 지급 단계를 거치며 계속 상태가 변화  
환불이 발생하면 이미 종료된 주문은 그대로지만 정산 금액은 환불액만큼 변화한다
